## Plan: Implement Admin Attendance Panel Design

### Goal
Replace the bare `AdminAttendancePanel.tsx` scaffold with an implementation that matches the existing admin UI pattern used by `AdminUsersPanel.tsx` and `AdminEventsPanel.tsx`, and ensure the Attendance sidebar tab renders it correctly.

### Findings
- `AdminAttendancePanel.tsx` is currently self-contained, minimally styled, and does not match the shared admin design.
- `AdminSidebar.tsx` already defines an `attendance` tab, but `Admin.tsx` currently renders users for `users` and events for every other tab, so attendance is not wired in.
- `AdminTopbar.tsx` labels every non-user tab as `Event Management` and shows a disabled create button for attendance with `New Event` text.
- `src/types/attendance.ts` is imported but does not currently exist.
- Supabase attendance APIs exist but are under-typed and `updateAttendance` does not call `.select().single()`, so the returned value is not useful for optimistic row replacement.
- The attendance migration defines `id`, `member_id`, `event_id`, `checked_in_at`, and `created_at`, with foreign keys to `members` and `events`.

### Implementation Steps
1. Add `src/types/attendance.ts` with an `AttendanceRecord` type covering the migration fields and optional joined `member`/`event` data for display.
2. Update `api.getAttendance` in `src/lib/supabase.ts` to select attendance rows with related member and event fields, ordered by latest check-in.
3. Update `api.updateAttendance` to return a selected single row, typed consistently, after changing `checked_in_at`.
4. Keep `api.deleteAttendance` behavior, but type the `id` and return shape consistently with the existing style.
5. Rebuild `AdminAttendancePanel.tsx` to follow the existing admin design:
   - Dark `section` layout with `space-y-4`.
   - Search input with `HiOutlineSearch`.
   - Optional event filter populated from loaded attendance rows.
   - Rounded bordered table/grid container matching users/events panels.
   - Loading and empty states matching the existing row components.
   - Desktop inline actions and mobile dots menu matching `RowActions` behavior.
   - Rows showing member name/email fallback, event name/location/date fallback, and formatted check-in time.
   - Actions for refreshing check-in time and deleting a record.
   - Use functional `setAttendance` updates to avoid stale state after async actions.
6. Wire the panel into `Admin.tsx`:
   - Import `AdminAttendancePanel`.
   - Render users, events, or attendance explicitly based on `activeTab` instead of treating all non-user tabs as events.
7. Update `AdminTopbar.tsx`:
   - Show `Attendance Management` when `activeTab === 'attendance'`.
   - Hide or disable the create button cleanly for attendance so it does not show `New Event` on that tab.
8. Verify with the project’s normal checks, likely `npm run build` or the available typecheck/build script from `package.json`.

### Notes
- This plan avoids adding create-attendance/QR scanning because the immediate issue is that the panel lacks the existing admin design and is not wired into the tab rendering.
- If Supabase relationship aliases differ from the default foreign-key relationship names, adjust the attendance select clause after testing against TypeScript/build errors or Supabase response behavior.
